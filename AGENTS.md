# devin-outpost-provisioner

- This repository is the hand-off artifact for running Devin Outposts on a customer cluster (OpenShift first): two Helm charts and the org provisioner. Nothing in `charts/*/values.yaml`, the templates or `provisioner/src` may assume a cloud, a registry, a node label or a storage driver; cluster-specific choices are values (`values-openshift.yaml` is the worked example). Cloud deployments that consume this repo keep their own values files (e.g. playground-dsaas/eks-deployment).
- `devin-outpost-k8s` (https://github.com/CognitionAI/devin-outpost-k8s) is consumed unmodified at the commit in `charts/devin-outposts-platform/OPERATOR_REF`. Its chart is not committed: `make operator-chart` copies it into `charts/devin-outposts-platform/charts/` (gitignored) as the `operator` subchart, and `lint`/`package` depend on it. Bump `OPERATOR_REF`, `operator.image.tag` in the platform `values.yaml` and the `rev` in `provisioner/Cargo.toml` together. Never enable `operator.defaultPool`: pools are created per org by the provisioner.
- `make lint` (helm lint/template + kubeconform with CRD schemas) and `make provisioner-check` (fmt, clippy, tests) run offline and are what CI runs. The provisioner's tests parse the chart values (`PoolTemplate::parse_helm_values` on `values.yaml` + `values-openshift.yaml`), so a values change that breaks the pool template fails `cargo test`.
- `provisioner/` follows `devin-outpost-k8s` conventions: Rust 1.96 / edition 2024, rustdoc over README, `kube` server-side apply with field manager `org-provisioner`, CRD types imported from the operator crate at the pinned `rev`. Comments state constraints, never narrate a change.
- Worker security contract: UID/GID 1000, all capabilities dropped, no privilege escalation, `RuntimeDefault` seccomp, `shareProcessNamespace: true`, worker command `/usr/local/bin/outpost-entrypoint.sh`. On OpenShift the uid is allowed by the SCC RoleBinding the provisioner renders from `poolTemplate.namespace.roleBindings`. The worker image is Cognition's `devin-outpost-prod` unmodified; the golden home volume is derived from that image only, never from org-specific content.
- Secrets never enter git: the Devin token is a Kubernetes Secret (`provisioner.token.existingSecret`) or, on AWS only, a Secrets Manager id.
